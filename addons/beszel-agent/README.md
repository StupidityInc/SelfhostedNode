# addons/beszel-agent/

Deploys the Beszel **agent** (not the hub) and connects it to a
manually managed hub running on another node. The hub and Uptime
Kuma are NOT installed by this addon — set those up manually.

## Source

The Compose template lives at `beszel-agent/docker-compose.yml` (repo
root). This addon copies it to `/opt/stacks/beszel-agent/` at install
time. The `.env.example` at `beszel-agent/.env.example` is a reference
for operators; the runtime `.env` is generated by the installer.

## Behaviour

See `install.sh` for the exact contract. Behaviour matches the
pre-WP5 inline implementation in `bootstrap.sh:configure_beszel_agent`
(behavioural parity, not byte-identical — the helper functions were
moved into the addon so it stays self-contained).

## Pre-flight (required before running)

1. Hub must already be running on another node, reachable via
   Tailscale (100.64.0.0/10 or fd7a:115c:a1e0::/48).
2. Hub UI must have created a system entry; copy the public
   `KEY` and `TOKEN` from there.
3. `BESZEL_HUB_URL`, `BESZEL_AGENT_KEY`, `BESZEL_AGENT_TOKEN` must be
   exported (interactive mode prompts; non-interactive requires them).

## Mutual exclusion

None currently. If you want both `restic-host-native` and Beszel,
that's fine — they don't conflict.

## Re-run safety

`install.sh` is re-runnable:

- The compose file is overwritten with identical content on every run.
- The `.env` is regenerated with the latest exported values; existing
  credentials survive if the env vars are still set.
- `docker compose up -d` is idempotent.
- `addon_persist_flag INSTALL_BESZEL_AGENT true` upserts the key in
  `/etc/homelab/node.env` (no duplicate lines).

When run from `bootstrap.sh --beszel-agent`, the install happens after
core (Tailscale + UFW + lobaro + exit-node apply) — failure aborts the
bootstrap run; the operator sees the error and re-runs with the flag.
